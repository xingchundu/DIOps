# 设计说明：Oracle SQL 智能诊断与优化工具

## 1. 目标与边界
| 目标 | 做法 |
|---|---|
| 输入 SQL_ID，得到完整诊断证据 + 优化建议 | 30 个采集章节 → 23 条规则 → DOCX |
| 不安装、Linux 直接执行 | Go 纯静态二进制 + go-ora（不依赖 Instant Client），`CGO_ENABLED=0` |
| 不伤生产库 | 只读 SELECT、单连接、单语句超时、行数上限、`--dry-run` 预览、报告附采集审计清单 |
| 建议可信可验证 | 每条结论必带：依据 / 建议 / 候选 SQL / **回滚** / 风险 / 验证方法 / 可信度 / 实施成本 |
| 不被 AI 绑架 | 规则引擎独立；AI 仅归纳，默认关闭，默认只连本机 |
边界：不自动执行任何变更；不做 SQL 自动改写成"保证等价"的承诺；不替代 DBA 评审。

## 2. 总体架构（单进程四层）
```
CLI(options) ─► 采集层 collect ─► Snapshot(JSON,可落盘) ─► 规则引擎 RunRules ─► 渲染层(DOCX/HTML/JSON)
                 │  DB 抽象(只读)            ▲ 离线 --input 复跑            └► 可选 AI 归纳
                 └─ 环境探测/降级/审计
```
* **采集层与分析层以 Snapshot 解耦**：采集只拿证据，不做判断；规则只读 Snapshot。因此可离线复跑规则、做前后对比、日后扩展 MySQL/达梦等只需换采集适配器。
* **每章节独立容错**：视图无权限 / LONG 列读取失败 / 版本差异 → 该章节标黄并降级，不中断整份报告。
* **DB 抽象** `Query(ctx, sql) → 字符串表`，驱动只在 `db_oracle.go` 中出现；`-tags nodriver` 可在无驱动环境编译与自测。

## 3. 采集清单（对照附件 1 的 27 章，新增 3 章）
01 环境/RAC 实例 · 02 SQL 基本信息（按实例/子游标）· 03 完整 SQL 文本 · **04 SQL 结构解析（新）** · 05 DBMS_XPLAN · 06 计划明细（含谓词/分区/TEMP）· 07 E-Rows/A-Rows ·
08 绑定变量（字符串脱敏）· 09 计划漂移 · 10 ASH · 11 AWR 趋势 · 12 AWR 历史计划 · 13 涉及对象 · 14 表统计（含 STALE/并行度）· 15 字段 · 16 列统计（NDV/NULL%/选择率）·
17 直方图热点值 · 18 索引（LOCAL/GLOBAL、可见性）· 19 索引列 · 20 函数索引表达式 · 21 分区键/类型 · 22 分区 · 23 约束 · 24 段空间 · 25 扩展统计 ·
26 Profile/Baseline/Patch/Directive · 27 会话阻塞 · **28 工作区/TEMP 溢出（新）** · **29 优化器与实例参数（新）** · 30 值频率采样（显式开启）· 附录 A 采集审计清单（新）。

关键设计点
* **定位 SQL**：GV$SQL 全部子游标；每个 PLAN_HASH_VALUE 取最近活跃子游标，优先当前连接实例；指标用独立聚合查询，不受展示行数截断。
* **CDB**：直连 PDB 服务名，或 `--pdb` 会话级切换；DBA_HIST 在 PDB 的可用性取决于 awr_pdb_autoflush。
* **权限降级**：探测 `dba_tables` 可读性，不可读则全部改用 ALL_*。
* **LONG/CLOB**：SQL 文本用 `GV$SQLTEXT_WITH_NEWLINES` 分片拼接；HIGH_VALUE / DATA_DEFAULT / 函数索引表达式读取失败自动降级。
* **License 友好**：按 `control_management_pack_access` 自动决定是否碰 AWR/ASH；`--no-awr` 强制关闭；不使用 SQL Monitor/Tuning Pack。
* **安全**：用户输入（SQL_ID、表名、列名、PDB 名）一律正则白名单后内联；采样列名带双引号；字符串绑定值与敏感列采样值脱敏；快照文件权限 0600；密码可走环境变量。
* **数据分布两层**：默认只用字典统计与直方图（零开销）；`--sample` 才做 `SAMPLE BLOCK` 采样，比例上限 20%。

## 4. 规则引擎（23 条，`--list-rules`）
| 类别 | 规则 |
|---|---|
| 总体 | R01 单次耗时过高 · R04 命中率低 · R05 I/O 等待占比 · R06 RAC gc 等待 |
| 访问路径 | R02 大结果集走索引回表 · R13 大表全扫但返回比例低（**自动生成 INVISIBLE 候选索引**）· R14 隐式转换/函数包裹列 · R07 函数谓词与函数索引不匹配（**用采样绑定值自动改写**）· R18 笛卡尔积 |
| 统计与分布 | R03 E/A-Rows 偏差 · R08 统计过期/缺失/缺直方图 · R09 数据倾斜 |
| 对象设计 | R10 分区裁剪/GLOBAL 索引 · R12 冗余/低效索引线索 · R16 LIST 分区无 DEFAULT · R17 聚簇因子 |
| 稳定性 | R11 绑定变量窥探/多计划 · R20 历史劣化/计划突变（AWR）· R21 游标过多/字面量 |
| 资源 | R19 排序/哈希溢出 TEMP · R22 阻塞/锁等待 |
| 环境 | R15 dblink/远端网关 · R23 优化器参数异常 |
设计原则：①规则是"线索"，措辞保守（"需结合…判断"）；②每条规则带阈值（`--th-*` 可调）与可信度；③单条规则 panic 不影响其它；④候选 SQL 用真实库/表/列名，并配套**回滚语句**（DROP INDEX / RESTORE_TABLE_STATS / DROP_SQL_PATCH）。
扩展新规则：在 `rules.go` 增加一个 `func(c *rctx) []Finding` 并登记到 `Rules`。

## 5. 报告（DOCX）结构
标题与环境行 → 目录域 → 关键指标 → **执行摘要与优化路线图（新）** → [AI 归纳] → [优化前后对比] → 诊断结论（分级、可信度、依据、建议、候选 SQL、**回滚方式（新）**、风险、验证）→ 采集证据 30 章 → 附录 A 审计清单 → 附录 B 口径。
版式：横向 A4、自适应列宽、斑马纹、表头跨页重复、数值列右对齐；**宽表自动拆分"各行相同的公共字段"**，避免 30 列挤成一团；DOCX 由标准库手写生成，不依赖 Word/任何库。同一份数据可出 HTML / JSON。

## 6. 优化闭环
SQL_ID → 采集 → 规则 → 建议 → 测试库验证 → 变更 → 同 SQL_ID 重采 `--compare` → 前后对比报告。批量：多个 SQL_ID 横向对比（耗时/行数/逻辑读/命中率/首要问题）。

## 7. 路线图（建议分期）
* **一期（本包）**：单机/RAC/CDB 采集、23 规则、DOCX、快照与对比、批量、可选 AI。
* **二期**：共享池老化后从 AWR 兜底还原指标与计划；SQL 文本改用成熟解析器（含 CONNECT BY / (+) / MODEL）；自建定时快照守护（替代 AWR）；候选索引基于工作负载（多 SQL 汇总）去重合并。
* **三期**：优化验证自动化（在测试库用 INVISIBLE 索引 / SQL Patch 做 A/B 并产出对比）；Web 工作台与平台集成（任务调度、权限、历史报告库）；多数据库适配（MySQL/PG/达梦/金仓）。

## 8. 已知局限
采集 SQL 未在真实 Oracle 上实测（见 README）；SQL 解析为轻量实现；RAC 下 DBMS_XPLAN 仅能取当前实例游标（GV$SQL_PLAN 明细覆盖跨实例）；规则阈值为通用经验值，需按业务调整；报告的"实施成本"为经验估计。
