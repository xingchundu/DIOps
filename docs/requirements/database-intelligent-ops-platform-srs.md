## 2. 引言

### 2.1 文档目的

本文档为**数据库智能平台（基于 Prometheus）**的需求分析说明，面向产品、研发、测试及运维团队，明确平台的功能边界、业务规则、非功能约束及验收标准，作为系统设计与开发的权威输入依据。

### 2.2 背景与问题域

当前企业数据库运维常见痛点：

- 数据库类型多样（Oracle / MySQL / PostgreSQL / 信创等），缺乏统一管控入口。
- 监控数据分散、告警风暴频发，运维响应效率低。
- 故障排查依赖人工经验，平均恢复时长（MTTR）偏高。
- SQL 质量管控不足，慢 SQL、全表扫描等问题反复出现。
- 自动化程度不足，重复性运维占用大量人力。
- 缺乏统一报表与 SLA 度量体系，运维价值难以量化。

本平台以 **Prometheus** 为核心监控引擎，融合 **AI 智能分析**，构建覆盖「发现问题 → 分析问题 → 解决问题 → 自动化」闭环的数据库智能运维体系。

### 2.3 术语与缩略语

| 术语/缩略语 | 说明 |
|-------------|------|
| Prometheus | 开源时序监控系统，用于指标采集、存储与告警 |
| Exporter | Prometheus 采集端适配器，将数据库/主机指标暴露为 HTTP 接口 |
| Alertmanager | Prometheus 配套告警路由与抑制组件 |
| CMDB | 配置管理数据库，记录 IT 资产及其关系 |
| RCA | Root Cause Analysis，根因分析 |
| RAG | Retrieval-Augmented Generation，检索增强生成，用于 AI 问答 |
| RBAC | Role-Based Access Control，基于角色的访问控制 |
| SLA | Service Level Agreement，服务级别协议 |
| AWR | Automatic Workload Repository，Oracle 性能快照报告 |
| ASH | Active Session History，Oracle 活跃会话历史 |
| MTTR | Mean Time To Repair，平均故障恢复时长 |
| DBA | Database Administrator，数据库管理员 |
| ChatOps | 通过自然语言交互驱动运维操作的模式 |
| 信创 | 信息技术应用创新，特指国产化软硬件体系 |
| 平台库 | 本智能平台自身使用的后台 **Oracle** 数据库，存储平台配置、用户、审计等元数据 |

## 3. 系统概述

### 3.1 系统定位

数据库智能平台是面向企业 DBA 及运维团队的**一站式数据库治理产品**，以 Prometheus 生态为监控底座，整合 AI 分析引擎，实现**资产管理、实时监控、智能告警、性能优化、自动化处理及报表运营**等核心能力的统一融合。

### 3.2 系统架构分层

平台分为三层：**资源层（被管资源）→ 交互层（接入协议）→ 功能层（业务能力）**，并向上提供外部接口服务。

| 架构层 | 组成 | 说明 |
|--------|------|------|
| 功能层 | 10 大业务模块 | 故障诊断、监控、告警、SQL 优化、自动化运维、AI 分析等 |
| 交互层 | JDBC/ODBC · Agent · SSH · 分布式 · 跨网段 | 平台与底层数据库资源的连接与数据采集 |
| 资源层 | 物理机 · 云主机 · 信创数据库 · 云 RDS | 纳管的数据库实例与基础设施 |
| 外部接口 | 统一监控 · 云管 · ITSM · 短信平台等 | 与企业现有系统集成对接 |

### 3.3 核心业务流程

监控采集 → 告警触发 → AI 根因分析 → 自动化处理 → SQL 优化建议 → 报表汇总。

### 3.4 支持的数据库类型（被管端）

> **V1.1**：一二期以 **Oracle** 为重点；MySQL/PostgreSQL 监控同步实现**基础版**；SQL Server、信创、云托管等以**三期**为主。

| 类别 | 产品 | 支持版本/备注 |
|------|------|----------------|
| 商业数据库 | Oracle ★（一二期重点） | 11g / 12c / 19c（一二期主要验证 **19c**） |
| 商业数据库 | SQL Server | 2016 / 2019 / 2022（**三期**） |
| 开源数据库 | MySQL | 5.7 / 8.0 |
| 开源数据库 | PostgreSQL | 12 / 13 / 14 / 15 |
| 信创数据库 | 达梦（DM） | DM8（**三期**） |
| 信创数据库 | 人大金仓（KingbaseES） | V8R6+（**三期**） |
| 信创数据库 | openGauss | 3.x / 5.x（**三期**） |
| 云托管 | 阿里云 RDS / 华为 GaussDB / 腾讯 TDSQL 等 | 云 API 接入（**三期**） |

### 3.5 平台自身技术选型（V1.1 明确）

平台以 **Oracle 19c** 作为自身后台数据库，存储所有平台元数据（用户账号、权限配置、CMDB 资产、告警记录、审计日志、报表数据等）。

| 组件 | 选型 | 说明 |
|------|------|------|
| 平台后台数据库 | Oracle 19c | 结构化元数据：用户、权限、CMDB 资产、配置、告警记录、审计日志、巡检结果、报表数据等 |
| 用户认证存储 | Oracle 19c | 登录用户（用户名、密码哈希、角色、租户归属、登录日志）存平台 Oracle 库 |
| 时序监控数据 | Prometheus + VictoriaMetrics | 指标时序**独立存储**，**不写入** Oracle 平台库；Prometheus 采集，VictoriaMetrics 长期存储 |
| 日志数据 | Elasticsearch / Loki | 慢 SQL、操作日志等非/半结构化日志入 ES；平台库仅存摘要索引 |
| AI 知识库 | Milvus / pgvector | 向量库独立部署，与平台 Oracle 库经 API 交互 |
| 缓存层 | Redis | 会话 Token、热点配置缓存、实时监控摘要缓存 |

#### 3.5.1 平台 Oracle 库核心数据模型（概要）

| Schema/表组 | 存储内容 |
|---------------|----------|
| SYS_USER / SYS_ROLE / SYS_PERMISSION | 用户账号、密码哈希（BCrypt）、角色、菜单权限、数据权限范围 |
| SYS_TENANT | 租户信息、资源配额、租户状态 |
| SYS_AUDIT_LOG | 全量操作审计（不可删除，Oracle **按月分区**） |
| CMDB_INSTANCE / CMDB_HOST / CMDB_CLUSTER | 实例、主机、集群资产 |
| CMDB_APP_DB_RELATION | 应用与数据库依赖拓扑 |
| ALERT_RULE / ALERT_RECORD / ALERT_NOTIFY | 告警规则、历史、通知记录 |
| MONITOR_CUSTOM_PANEL | 自定义监控面板（PromQL、布局） |
| SQL_SLOW_SUMMARY / SQL_OPTIMIZE_RECORD | 慢 SQL 摘要、优化建议历史（详细日志在 ES） |
| INSPECT_TASK / INSPECT_RESULT | 巡检任务与结果摘要 |
| BACKUP_POLICY / BACKUP_RECORD | 备份策略与历史元数据 |
| REPORT_CONFIG / REPORT_RECORD | 报表模板与生成记录 |

#### 3.5.2 Oracle 平台库连接要求

- 版本 **19c（19.3+）**，字符集 **AL32UTF8**。
- 连接：**JDBC Thin**，连接池 **HikariCP**；建议初始 **50**、最大 **200**（按并发调整）。
- 应用账号**最小权限**：仅平台 Schema 的 CRUD，**禁止** DBA 权限。
- 平台库与被管 Oracle 实例**物理隔离**，**禁止**共用同一实例。
- 平台库开启审计（**Unified Auditing**），记录 DDL。

## 4. 用户角色与权限模型

### 4.1 角色定义

| 角色 | 典型用户 | 主要职责与权限范围 |
|------|----------|-------------------|
| 超级管理员 | 平台管理员 | 全局配置、用户与租户管理、操作审计查看、系统参数 |
| 数据库管理员（DBA） | 资深 DBA | 全库资产管理、监控规则、告警处理、SQL 优化、备份恢复、自动化策略 |
| 运维工程师 | 运维人员 | 日常巡检、告警响应、会话管理、基础 SQL 执行、查看报表 |
| SQL 审核员 | 开发 DBA / 数据审核岗 | SQL 审核、发布上线审批、优化建议查看 |
| 只读用户（观察者） | 业务负责人 / 领导 | 查看监控大盘、报表、SLA，不可操作 |
| 开发人员 | 应用开发 | SQL 性能查询、慢 SQL 提交优化、自助 SQL 评审 |

### 4.2 权限控制原则

- **RBAC**：权限绑定角色；角色权限数据存储在平台 Oracle 库 **SYS_ROLE / SYS_PERMISSION**。
- **用户认证**：用户名+密码（**BCrypt** 存平台库）；支持 LDAP/SSO 对接。
- **多租户隔离**：租户间数据、配置、告警完全隔离。
- 敏感操作（删除、Kill Session、执行自动化脚本）需**二次确认或审批流**。
- 操作审计写入 **SYS_AUDIT_LOG**，不可删除、不可篡改。

### 5.2 监控中心

解决「发生了什么」——**一二期以 Oracle 监控为核心完整实现**；MySQL/PG **基础版**同步实现。

#### 5.2.1 监控指标需求

| 监控维度 | 核心指标 | 采集方式 |
|----------|----------|----------|
| 主机层 | CPU/内存、磁盘 IO（iops/吞吐）、网络、文件句柄 | node_exporter → Prometheus |
| 数据库通用 | 连接数（active/idle/max）、QPS/TPS、锁等待、慢 SQL 数、**表空间使用率** | db_exporter（各类型适配） |
| Oracle 专项 ★ | Buffer/Shared Pool 命中率、Redo 切换、AWR Top SQL、各表空间使用率、**ASH 等待**、会话（Active/Inactive）、**PGA/SGA**、Archive 空间、**Data Guard 同步延迟**（如有） | oracle_exporter / JDBC（**一二期重点**） |
| MySQL 专项 | Binlog 延迟、InnoDB Buffer Pool、复制延迟、慢查询日志 | mysqld_exporter |
| PostgreSQL 专项 | pg_stat_activity、死锁、Vacuum、WAL | postgres_exporter |
| 存储层 | 表空间/数据文件增长、归档日志空间 | 各类型 exporter |

#### 5.2.2 监控功能需求

| 编号 | 功能点 | 需求描述 |
|------|--------|----------|
| F-09 | 实时指标展示 | 30s 内采集并在 Dashboard 呈现；趋势、热力图、Top-N；**实例列表总览 + 实例详情**双层视图 |
| **F-09a** | **数据库实例监控详情页** ★ | **V1.1 新增**：每个纳管实例独立详情页，规范见 [5.2.3](#523-数据库实例监控详情页规范-f-09a) |
| F-10 | 自定义监控项 | DBA 自定义 PromQL 与面板；配置存 **MONITOR_CUSTOM_PANEL** |
| F-11 | 精细化监控 | 实例级、集群级、数据库级、表级四类视图 |
| F-12 | 监控数据分析 | 任意时间段回溯；多实例/多指标对比 |
| F-13 | 监控数据存储 | Prometheus 本地 + VictoriaMetrics/Thanos；热 30 天、冷 1 年；**时序数据不入 Oracle 平台库** |

#### 5.2.3 数据库实例监控详情页规范（F-09a）

监控列表点击实例名进入独立详情页，聚合基本信息、实时性能、历史趋势、告警、SQL 等；**一二期以 Oracle 详情页为完整标准**。

| 区块/Tab | 展示内容 | 字段/指标要点 |
|----------|----------|----------------|
| ① 基本信息 | 实例元数据 | 名称、类型、版本（如 Oracle 19.3.0.0）、主机 IP/端口/OS、字符集、时区、状态、纳管/最后采集时间、租户/业务线/环境标签、健康分（0–100 彩色）、**Data Guard 角色**（Oracle） |
| ② 实时性能 | 关键指标仪表盘 | 主机 CPU/内存；连接数 Active/Idle/Max；QPS/TPS；**Buffer Cache**（Oracle，&lt;95% 橙色）；**Shared Pool**；Active Session；**等待事件 Top5**（约 30s 刷新）；锁等待数（&gt;0 红色） |
| ③ 表空间 | 空间使用 | 各表空间名称/总/已用/剩余/使用率（进度条）；&gt;80% 橙、&gt;90% 红；7/30 天趋势；归档空间（Oracle）；临时表空间 |
| ④ SQL 分析 | SQL 性能快照 | 慢 SQL Top10（文本截断约 100 字、平均耗时、次数、最后执行时间）；跳转 SQL 优化模块；全表扫描 SQL 趋势；**执行计划变更告警数**（AWR 对比） |
| ⑤ 会话 | 当前会话 | 活跃/等待/空闲会话数；列表（SID、Serial#、User、程序、状态、等待事件、时长）；**Kill Session**（权限）；**阻塞关系树** |
| ⑥ 告警汇总 | 近期告警 | 近 7 天列表（时间、P1–P4、内容、处置状态）；按天趋势；未处置红角标；跳转告警中心（本实例过滤） |
| ⑦ 历史趋势 | 时间范围 | 1h/6h/1d/7d/30d/自定义；折线图联动缩放；关键指标 **CSV 导出**；**与上周同期基线对比**（橙色虚线） |
| ⑧ AWR 快照（Oracle） | AWR 报告 | 快照列表（起止时间、DB Time）；选区间一键 **HTML/PDF**；Top 10 SQL（DB Time）；等待事件饼图 |
| ⑨ 操作记录 | 平台操作历史 | 本实例：连接、SQL、Kill、参数、备份等；来源 **SYS_AUDIT_LOG**（按实例过滤） |

#### 5.2.4 详情页交互规范

- URL：`/monitor/instance/{instance_id}/detail`，可分享。
- 顶栏：实例名、状态徽标、健康分、最后刷新、手动刷新。
- 默认自动刷新 **30s**，可关闭。
- Tab 切换用**前端路由**，不整页重载。
- 超阈值：**警告=橙色，紧急=红色**。
- 列表点实例名 → 详情；详情可带 **instance_id** 跳转 SQL 优化、会话管理、告警中心。

#### 5.7.1 与 §5.4 F-29「数据库巡检」的边界

| 维度 | F-29（数据库管理模块） | F-53（自动化运维） |
|------|------------------------|-------------------|

#### 5.7.2 平台 Oracle 库对象（实施建议命名）

> 表名可在详细设计中微调，但必须满足「策略可版本化、执行可审计、与实例/租户可关联」。

| 能力分组 | 建议核心表 / 对象 | 说明 |

#### 5.7.3 关键验收要点（节选）

- **F-47**：任一备份任务在 **BACKUP_RECORD** 中可查到状态流转（已调度/成功/失败/已验证）；恢复演练成功须有独立记录。
- **F-48**：任一自愈动作可配置「仅告警不执行 / 审批后执行 / 自动执行」；执行前后关键指标写入 **SELF_HEAL_EXEC_LOG**。
- **F-49**：DAG 失败时须标明失败节点；支持人工「从节点重试」；全流程映射 **RUNBOOK_EXEC_LOG**。
- **F-50**：从工单创建到关单，**OPS_SERVICE_LOG** 时间线完整；敏感子步骤（改密、授权）二次确认。
- **F-52**：未审批版本不可对生产实例执行；**SCRIPT_EXEC_LOG** 与运行用户、代理节点可追溯。
- **F-53**：批量任务进度可查询；最终报告与 **INSPECT_RESULT** 批次一致并可下载归档。

### 6.2 可用性与可靠性

- 平台自身 **SLA ≥ 99.9%**（年停机 &lt; 8.76 小时）。

- 监控数据不丢失：采集端缓冲与补传。
- 告警**双通道** failover。
- 平台服务 **HA**；单节点故障不中断采集。

### 6.3 安全需求

## 9. 约束与假设

### 9.1 技术约束

- Prometheus **≥ 2.40**。
- **平台后台数据库强制 Oracle 19c（19.3+）**，不可替换为其他数据库产品。
- 初始化需 **DBA 级**账号；运行时使用**最小权限**应用账号。
- 推荐 **K8s**；最低 **Docker Compose**。
- AI：OpenAI 兼容 API 或私有化 LLM。
- Agent：CPU &lt; 5%，内存 &lt; 100MB（目标）。

### 9.2 业务约束

- 不直接改生产业务数据；操作限于审核类 DDL/DML、会话、配置查看等。
- 自动 Kill/扩容等**默认关闭**，需策略授权。
- SQL **评审通过前禁止上线**。
- **平台 Oracle 库与被管 Oracle 实例物理隔离**（不同实例/主机）。

### 9.3 假设

- 被管实例与平台网络可达。
- 已准备**独立 Oracle 19c 平台库**及 SYS/SYSTEM 级初始化账号。
- ITSM 具备 REST 集成能力。
- AI 已通过合规审批。
- **一二期聚焦被管 Oracle + Oracle 平台库**；MySQL/PG 监控为基础版。
