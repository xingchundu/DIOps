# 监控中心 / 控制台 / 报表中心 设计说明

## 1. 健康评分（扣分制，可解释）

原来的问题：
- 加权平均（连通性 20% + 性能 30% + 负载 25% + 资源 25%）把单点严重问题摊薄：表空间 99% 的实例仍可能 90 分以上。
- 没采集到的指标按 50 分计，采集项少的库（达梦、MySQL）分数被平白拉低（例如 65 分但其实没有问题）。
- 负载用“活跃会话 / 固定 200”这类与实例配置无关的绝对值。
- 连接失败显示 0 分，和“分数很低”混在一起。
- 没有容量、锁、备份、主机等检查，分数说明不了问题。

现在的规则（`dbops-server/.../monitor/HealthScorer.java`）：

| 规则 | 说明 |
|---|---|
| 满分 100，逐项检查 | 正常不扣分；警告扣 10 分（轻微项 5 分）；严重扣 25 分 |
| 封顶 | 有任一严重项最高 59 分；有任一警告项最高 89 分。分数段与结论一一对应：**≥90 健康、60~89 关注、<60 严重** |
| 未采集 | 不扣分、不计入“已检查项”，界面显示“未采集” |
| 连接失败 | 不打分，显示“离线”和原因（如“用户名或密码错误”“连接超时”） |
| 数据过期 | 超过 3 个采集周期（至少 10 分钟）没有新数据，显示“数据过期”，不给结论 |

检查项（按库类型取适用项，阈值为 警告 / 严重）：

| 分类 | 检查项 |
|---|---|
| 可用性 | 实例状态（非 OPEN 严重）、监听未就绪、集群资源 OFFLINE、磐维集群状态、主备复制断开、1 小时内重启 |
| 容量 | 表空间最大使用率 85% / 95%（Oracle、达梦）、快速恢复区 80% / 90%、主机文件系统 85% / 95% |
| 性能 | 缓存命中率 <95% / <90%、log file sync 10 / 30 ms、本周期慢查询 10 / 100 条、Page Life Expectancy <300 / <60 秒、事务回滚比例 5% / 20%、ORA-4031、检查点未完成 |
| 会话与锁 | **连接数占最大连接数** 80% / 95%（Oracle processes、MySQL max_connections、PG/磐维 max_connections、达梦 MAX_SESSIONS）、阻塞 60 / 300 秒、锁等待 5 / 20 个、空闲事务、死锁、MySQL 运行线程 30 / 80 |
| 主机 | CPU 80% / 95%、内存 90% / 97% |
| 数据保护 | 最近全备 7 / 14 天前、未开启归档 |

评分明细（扣分项、各分类结论、关键指标）随每次采集存入 `MONITOR_METRIC_SAMPLE.HEALTH_DETAIL`，实例详情“基本信息”页展示。

## 2. 监控中心

`GET /api/monitor/board` 一次返回全部实例（最新样本 + 近 2 小时走势 + 告警聚合，不逐实例查库）。

- 顶部概况：全部 / 严重 / 离线 / 关注 / 健康 / 无数据 / 未处理告警，点击即筛选。
- 卡片按严重程度排序：严重 → 离线 → 关注 → 无数据 → 健康。
  - 在线：CPU、连接（当前 / 上限，带占比条）、活跃会话、表空间（或命中率），CPU 近 2 小时走势，最主要的 2 个问题。
  - 离线：连接失败原因与检测时间。
  - 未采集：可直接点“采集”。
- 可按环境 / 业务线 / 库类型分组；卡片 / 列表两种视图；每 60 秒自动刷新（页面不可见时暂停）。
- 页面右上角“评分规则”说明评分方法。

## 3. 控制台

`GET /api/monitor/dashboard`

- 一句话结论：“3 个实例需要立即处理：1 个严重、2 个离线；未处理告警 3 条（P1 2 条）”。
- 关键数字：纳管实例、健康率、未处理告警（按级别）、SQL 问题、待办。
- 需要关注的实例（附最主要的问题）、健康分布与按库类型统计。
- 近 7 天告警（按级别堆叠）、最新未处理告警。
- 容量风险（表空间 / 文件系统 ≥85%、连接数 ≥80%）、SQL 情况、待办（待审 SQL 工单、服务工单、24 小时内备份失败）。

## 4. 报表中心：运行报告

`GET /api/monitor/report?type=DAY|WEEK|MONTH|CUSTOM&from&to&env&instanceId`

日报（昨天）、周报（上周一至周日）、月报（上月）、自定义；可按环境或单个实例出报告。

| 章节 | 内容 |
|---|---|
| 摘要 | 自动生成结论（可用率与中断实例、告警环比与解决耗时、容量风险、SQL、备份失败）+ 关键数字 |
| 可用性与健康 | 每个实例的可用率、中断次数、估算中断时长、平均 / 最低健康分、当前等级 |
| 告警 | 每日按级别趋势、规则 Top 10、实例 Top 10、MTTA / MTTR、环比 |
| 容量 | 期末表空间 / 文件系统 / 连接数占比，以及期间变化 |
| SQL | 新增问题（按规则）、性能波动（按原因）、最慢 SQL Top 10 |
| 运维工作 | 备份、巡检、SQL 审核、服务工单 |

支持“打印 / 导出 PDF”（只打印报告正文）和各表“导出 CSV”（Excel 直接打开）。
原 Node `/api/reports/*` 已删除：其中巡检汇总查询的列不存在、容量查询的表不存在、`FETCH FIRST n ROWS` 缺 `ONLY`，几个页签实际一直是空的。
