# DIOps 数据库智能平台 — 离线安装说明

**产品版本：{{VERSION}}** · Linux x64 · 无需访问互联网

本包已内置 **Java 主服务**、Node 兼容组件、网页、SQL/AI 模块及 Node/Python 运行环境。客户机只需能访问 **Oracle 平台库**（Thin 模式，无需安装 Oracle 客户端）。

---

## 1. 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux x64（CentOS 7+、RHEL、Ubuntu 等） |
| 工具 | `bash`、`tar`、`openssl`（生成 HTTPS 证书） |
| 网络 | 应用服务器 → Oracle **平台库** 端口（通常 1521）可达 |
| 防火墙 | **仅对外开放** `HTTPS_PORT`（默认 **18443**） |

不需要：Node、Java、Python、Maven、npm、Oracle Instant Client。

---

## 2. 解压

```bash
tar -xzf diops-offline-{{VERSION}}.tar.gz
cd diops
```

（压缩包文件名中的版本号与目录内 `VERSION` 文件一致。）

---

## 3. 配置数据库（唯一必改配置文件）

编辑 **`config/backend.env`**：

```env
DB_HOST=192.168.1.10
DB_PORT=1521
DB_SID=ora19c
DB_USER=monitor
DB_PASSWORD=你的密码
```

- 使用 **服务名** 时：删除 `DB_SID`，改为 `DB_SERVICE_NAME=ORCLPDB1`
- 或一行连接串：`DB_CONNECT_STRING=192.168.1.10:1521/ORCLPDB1`
- `JWT_SECRET` 可保持占位；**`bin/install.sh` 会自动生成**
- **`HTTPS_PORT`**：浏览器访问端口，默认 `18443`（勿与已有服务冲突）

---

## 4. 初始化平台库（DBA 执行，仅需一次）

在能连上 Oracle 的机器上，用 **与上面相同的用户** 执行建表脚本：

```bash
sqlplus monitor/密码@192.168.1.10:1521/ora19c @sql/init.sql
```

无 `sqlplus` 时，可用 **PL/SQL Developer** 等工具执行 `sql/init.sql`：

- 脚本开头已含 `SET DEFINE OFF` / `SET SCAN OFF`（避免 JSON 里 shell 命令的 `&&` 触发 **Enter value for** 弹窗）。
- 若仍弹窗：在 PL/SQL Developer 菜单 **Tools → Preferences → SQL Editor** 中关闭 **“Prompt for substitution variables”**，或执行前先输入 `SET DEFINE OFF`。

本安装包的 `sql/` 目录含 **`init.sql`**（已合并建表与 **SYS_LICENSE 授权表**），以及可选 **`license_tables.sql`**（已建库但缺授权表时单独执行）；`backend/` 下**不含** SQL。

若报 ORA 错误或登录后提示表结构不完整，请确认 `init.sql` 已由平台库用户**完整执行到底**（无报错中断）；仍失败请联系厂商并提供报错行号。

**说明：** 被管数据库（MySQL、其他 Oracle 等）在控制台 **资产管理** 里纳管，不写在 `backend.env` 里。

---

## 5. 安装与启动

```bash
chmod +x bin/*.sh
# 首次可直接 start（会自动执行 install.sh：证书、Python 模块、同步配置、检测平台库）
./bin/start.sh
# 也可分步：./bin/install.sh 后再 ./bin/start.sh
./bin/status.sh     # 可选：查看进程与健康检查
```

**访问：**

```text
https://服务器IP:18443/
```

（端口以 `config/backend.env` 中 `HTTPS_PORT` 为准。证书为安装时生成的自签名证书，浏览器需选择「继续访问」。）

默认账号（**登录后请立即改密**）：

| 账号 | 密码 |
|------|------|
| admin | Admin@123456 |
| dba | Dba@123456 |

**自检：**

```bash
curl -k https://127.0.0.1:18443/health
```

应返回 JSON，`status` 为 `ok`。

## 7.5 版本升级（存量客户）

适用于：已安装旧版离线包，更换为新版 `diops-offline-*.tar.gz`，**平台库保留不动**。

### 升级前必读

1. **备份 `config/backend.env` 整文件**（重点三项，升级后必须原样写回）：

   | 变量 | 说明 |
   |------|------|
   | `DBOPS_SECRET_KEY` | 被管库密码、SSH 凭据加密密钥。**更换后**库内已存密码无法解密，监控会报「凭据解密失败」→ 须在 **资产管理** 中**重新保存**各实例/主机密码（**不必删除实例**） |
   | `JWT_SECRET` | 更换后所有用户需重新登录 |
   | `AI_INTERNAL_TOKEN` | 更换后 AI 分析/SQL 优化内部调用可能失败 |

2. **`install.sh` 仅在密钥为空或过短时才会自动生成新密钥**。升级前请确认三项已配置且足够长；升级后**用备份覆盖**，不要误用新随机密钥。

3. **平台库增量 SQL**：离线包内**只有** `sql/init.sql` / `sql/license_tables.sql`，**不含**版本间全部 `migration_*.sql`。请向厂商索取「从当前版本到目标版本」的增量脚本，由 DBA 在**原平台库用户**下执行后再启动新版本。

4. **平台授权**：授权绑定平台库 **DBID**（登录页机器码）。只升级应用、不换平台库时，一般**无需重签**；到期或换库后在登录页 **导入授权**（可未登录导入）。说明见包内或厂商提供的 [LICENSE.md](../../docs/LICENSE.md)。

### 升级步骤

```bash
./bin/stop.sh
cp config/backend.env config/backend.env.bak.$(date +%Y%m%d)   # 必做
# 解压新版本覆盖安装目录（保留 config/backend.env.bak 中的密钥）
# DBA 执行厂商提供的 migration 脚本
# 将备份中的 DBOPS_SECRET_KEY / JWT_SECRET / AI_INTERNAL_TOKEN 合入 config/backend.env
./bin/install.sh    # 证书、Python 模块；不会覆盖已足够长的密钥
./bin/start.sh
./bin/status.sh
```

**验收**：`curl -k https://127.0.0.1:<HTTPS_PORT>/health`；能登录；CMDB 实例非大量离线；授权状态正常。

**禁止**：用开发源码目录覆盖本安装包；将 `config/backend.env` 或 `certs/server.key` 外传；升级时无端更换 `DBOPS_SECRET_KEY` 且未在 CMDB 重录密码。

### 换应用服务器 / 升级后登录页提示「时间被回拨」

授权绑的是**平台库**，不是应用服务器。同一台平台库只换应用时，机器码不变，**不用重新申请授权**。登录页若出现「检测到系统时间被回拨，授权暂不可用」，多半不是时间，而是新服务器上的 `DBOPS_SECRET_KEY` 和库里 `SYS_LICENSE_STATE` 对不上。导入新的授权文件**不会**改写这一行，所以会每次都一样。

搬服务器或升级之前：

1. 从旧服务器把 `config/backend.env` 原样拷过来。至少 `DBOPS_SECRET_KEY`、`JWT_SECRET`、`AI_INTERNAL_TOKEN` 必须和旧服务器相同，不要在新机器上重新生成。
2. 启动时指定这个文件（`./bin/start.sh` 已使用安装目录下的 `backend/.env`，该文件由 `config/backend.env` 同步）。启动日志里应有 `[env] loaded … keys from …`，路径必须是刚拷过来的那份。
3. 不要删 `SYS_LICENSE`、`SYS_LICENSE_STATE`。

出现红字后按顺序查。

**1. 看 Java 日志 `logs/dbops-java.log` 是哪一句。**

- `SYS_LICENSE_STATE 校验失败（记录被修改，或 DBOPS_SECRET_KEY 未加载/已更换）`：密钥问题，做第 2 步。
- 没有这一句、只有时间回拨：才是平台库时间真的被往回改了，做第 4 步。

**2. 核对密钥有没有加载。**

```bash
grep -E '^DBOPS_SECRET_KEY=' config/backend.env
tr '\0' '\n' < /proc/$(pgrep -f dbops-server.jar | head -1)/environ | grep DBOPS_ENV_FILE
```

`DBOPS_SECRET_KEY=` 后面必须和旧服务器那一行完全一致。`DBOPS_ENV_FILE` 必须指向这份文件。空的、新生成的、或指向了别的目录，都会出现上述红字。改对后重启 `dbops-server`，不用重新导入授权。

**3. 旧密钥已经丢了。**

先确认平台库时间是对的（第 4 步的 SQL），再执行：

```sql
DELETE FROM SYS_LICENSE_STATE;
```

重启 Java。程序会按**当前**密钥重写这一行。`SYS_LICENSE` 里已导入的授权还在，不用再导入。

代价：库里用旧密钥加密的被管库密码、SSH 密码解不开，日志为「凭据解密失败」。到资产管理里把实例和主机密码重新保存一次，不要删实例。

**4. 确认是不是时间真的回拨。**

```sql
SELECT LAST_SEEN_MS,
       TO_CHAR(
         TIMESTAMP '1970-01-01 00:00:00 UTC'
         + NUMTODSINTERVAL(LAST_SEEN_MS/1000, 'SECOND'),
         'YYYY-MM-DD HH24:MI:SS'
       ) AS LAST_SEEN_UTC,
       TO_CHAR(SYS_EXTRACT_UTC(SYSTIMESTAMP), 'YYYY-MM-DD HH24:MI:SS') AS DB_UTC
FROM SYS_LICENSE_STATE
WHERE ID = 1;
```

`DB_UTC` 比 `LAST_SEEN_UTC` 早了 1 小时以上，才是时间被回拨。把平台库服务器的时间改回正确时间，等数据库时间超过 `LAST_SEEN_UTC` 后，大约 1 分钟内提示会自己消失。时间还没追上时，不要删这行记录。

## 11. 常见问题

**`install.sh` 报 `runtime/node 或 runtime/python 不完整`，且 `ls runtime/python/bin/python3.9` 不存在、`du -sh runtime/python` 为 0**

- 多为**有缺陷的旧离线包**：打包机把 `deps/python` 做成符号链接（如 `/opt/python39`）时，原样打进 tar，客户机无该路径导致目录为空。
- 客户机自检：`ls -la runtime/python` 若为 `-> /opt/python39` 之类，需向厂商索取**重打后的完整包**（内含实体 `runtime/python`，约 40MB+ 可执行文件与库）。
- **临时补救**（需厂商提供 Python 3.9 独立运行时 tar，或与打包机相同目录）：解压到 `runtime/python`，确保存在 `runtime/python/bin/python3.9` 且为 **linux x86_64** 可执行文件，再执行 `./bin/install.sh`。

**平台库连接失败**

- 核对 `DB_HOST` / 端口 / SID 或 `DB_SERVICE_NAME`
- 确认 `sql/init.sql` 已由该用户执行
- 查看 `logs/dbops-java.log` 中 `[DB] Oracle pool`

**页面能开但接口 502**

- `./bin/status.sh`，确认 `dbops-java` 为 running
- 等待启动后 10～20 秒再刷新

**监控无数据**

- 确认 Java 服务在运行（监控定时采集在 Java 侧）
- 在 **资产管理** 中纳管实例并检查连接

## 11b. 被管 Oracle 监控账号权限（部署）

纳管实例时填写的用户是 **被管库** 账号，**不是** `config/backend.env` 里的 `DB_USER`（平台库）。

在被管 Oracle 上建议创建专用用户（如 `diops_monitor`），至少：

```sql
GRANT CREATE SESSION TO diops_monitor;
GRANT SELECT ANY TRANSACTION TO diops_monitor;
GRANT LOGMINING TO diops_monitor;              -- 按需
```

**字典 / 动态性能视图（二选一，与采集 SQL 相关）：**

| 方式 | 命令 | 说明 |
|------|------|------|
| **推荐** | `GRANT SELECT ANY DICTIONARY TO diops_monitor;` | 可访问 `V$SESSION`、`V$SQL`、`DBA_DATA_FILES` 等，监控/SQL 洞察默认口径 |
| **备选** | `GRANT SELECT_CATALOG_ROLE TO diops_monitor;` | 企业禁止 ANY DICTIONARY 时用；**不能等同** ANY DICTIONARY，授后须自检 |

授权后在被管库执行（任一项报错即权限不足）：

```sql
SELECT COUNT(*) FROM v$session;
SELECT COUNT(*) FROM dba_data_files;
SELECT sql_id FROM v$sql WHERE ROWNUM = 1;
```

其他库类型（MySQL、PostgreSQL、达梦等）见安装包内 **`docs/monitor-target-db-privileges.md`**。
